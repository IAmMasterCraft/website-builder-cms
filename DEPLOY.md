# Deploying Gather on aaPanel (Apache + PHP-FPM + MySQL)

This guide puts Gather on a new (sub)domain of an aaPanel server running
**Apache**. You run the server commands yourself; nothing here needs a
password typed into chat or a file. Menu names differ a little between
aaPanel versions: if a label does not match, look for the nearest one.

Throughout, replace:

| Placeholder | Example |
|---|---|
| `<domain>` | `community.example.org` |
| `<site>` | the site folder aaPanel creates, `/www/wwwroot/community.example.org` |
| `<ver>` | the PHP version folder, `83` for PHP 8.3 |

## 0. What the server needs

- PHP **8.2 or newer** (8.3 recommended) as PHP-FPM, with the extensions
  `pdo_mysql`, `gd` (with WebP), `fileinfo`, `mbstring`, `sodium`,
  `openssl`, `zlib`, `json`, and preferably `intl` and `exif`.
  `exec()` and the other shell functions can stay disabled: Gather never
  calls them (backups are pure PHP).
- MySQL 8 or MariaDB 10.6+.
- A DNS **A record** for `<domain>` pointing at the server.

## 1. Build the archive (on your Mac)

```bash
cd projects/website-builder
PHP=/opt/homebrew/bin/php bin/check     # lint, tests, smoke test: must all pass
bin/package                             # -> dist/gather-<date>-<commit>.tar.gz
```

`bin/package` archives the committed code (commit first) and leaves out
`config.php`, everything under `storage/` and `public/uploads/`, the tests,
`dev-tools/` and developer notes. It uses
`COPYFILE_DISABLE=1 tar --no-xattrs --no-mac-metadata --exclude='._*'`, so no
macOS `._*` files reach the server, and it refuses to finish if a private file
slipped in. The archive contains one top folder, `gather/`.

## 2. Create the site

aaPanel → **Website → Add site**:

- Domain: `<domain>`.
- PHP version: 8.2 or newer (install it first from the **App Store** if it
  is not listed).
- Database: **MySQL**, create one here (name and user, e.g. `gather`), with a
  password generated by aaPanel. Character set **utf8mb4**. Keep the
  password in aaPanel; you will paste it into the installer form in your
  browser, never into chat.

Open the new site's **Settings**:

- **Site directory → Running directory**: choose `/public` and save. Only
  `public/` is then reachable from the web; `src/`, `storage/`, `config.php`
  and the rest are not.
- Keep **anti-cross-site attack (open_basedir)** on. Gather only reads inside
  the site folder and the system temp folder (`/tmp/`, which aaPanel's
  default already allows for uploads).
- **URL rewrite**: leave empty. Apache uses Gather's `public/.htaccess`.
- **SSL → Let's Encrypt**: issue a certificate, then switch on **Force
  HTTPS**. Do this **before** running the installer, so the installer records
  `https://<domain>` as the site address.

## 3. Upload and unpack

aaPanel → **Files** → open `<site>` → upload the archive. aaPanel has put a
few placeholder files in the folder (`index.html`, `404.html`, maybe
`.htaccess`); delete them, but **keep `.user.ini`** (aaPanel's open_basedir
file; it is immutable on purpose).

Then aaPanel → **Terminal** (or SSH):

```bash
cd <site>
tar -xzf gather-*.tar.gz --strip-components=1   # unpack gather/* into the site folder
rm gather-*.tar.gz
find . -name '._*' -type f -delete               # belt and braces
# Code belongs to root and is read-only for the web server (skip aaPanel's immutable .user.ini).
find . -path ./.user.ini -prune -o -exec chown root:root {} +
find . -path ./.user.ini -prune -o -type d -exec chmod 755 {} +
find . -path ./.user.ini -prune -o -type f -exec chmod 644 {} +
chmod 755 bin/*
# Only these two folders are writable by the web server user.
chown -R www:www storage public/uploads
```

The web server user (`www`) can only write to `storage/` and
`public/uploads/`. If PHP is ever tricked into writing a file, it cannot
change Gather's code. (A deploy user instead of root is fine too: what
matters is that `www` does not own the code.) During the install only, the
site folder itself is made writable for `www` so the wizard can create
`config.php` (step 5).

## 4. PHP settings

aaPanel → **App Store** → your PHP version → **Settings**:

- **Install extensions**: `fileinfo`, `intl`, `exif` if missing (`gd`,
  `mbstring`, `openssl`, `pdo_mysql`, `sodium`, `zlib` are normally built in).
  aaPanel's GD includes WebP; the System health page confirms it.
- **Configuration** (or **Configuration file**, `php.ini`):

  | Setting | Value | Why |
  |---|---|---|
  | `display_errors` | `Off` | errors go to `storage/logs/php-error.log` |
  | `expose_php` | `Off` | no PHP version header |
  | `upload_max_filesize` | `320M` | radio video up to 300 MB, audio up to 100 MB |
  | `post_max_size` | `330M` | a little above the upload limit |
  | `memory_limit` | `256M` | resizing large photos |
  | `max_execution_time` | `300` | big uploads and backup downloads |
  | `max_input_time` | `300` | slow uploads |

  If you never upload radio video, 120M / 128M is enough.
- **Disabled functions**: keep aaPanel's defaults.
- Restart (or reload) this PHP version.

## 5. Install

The installer only runs for someone who knows a **one-time install token**
that you create on the server. In the Terminal:

```bash
cd <site>
php -r 'echo bin2hex(random_bytes(16)), PHP_EOL;' > storage/install-token   # the token
cat storage/install-token                                                    # copy it for the form
chown www:www storage/install-token && chmod 600 storage/install-token
# let the wizard create config.php in the site folder (taken back after the install)
chown root:www . && chmod 775 .
```

(Instead of the file you can set the environment variable
`GATHER_INSTALL_TOKEN` for PHP-FPM.) Without a token `/install` only shows
these instructions. The file is deleted when the install finishes.

Then open `https://<domain>/install`:

1. **Database**: the **install token**, the **site address**
   (`https://<domain>`; it is pre-filled but check it, it is used in every
   email link), host `localhost` (or `127.0.0.1`), port `3306`, the database
   name, user and password from step 2. The wizard checks the connection
   (a failure shows a generic message; the details go to
   `storage/logs/php-error.log`), writes `config.php` (mode 640) with a fresh
   random `app_key`, and runs the migrations. Only your browser session can
   continue from here.
2. **Admin**: organisation name and the first **super admin** (name, email,
   password of at least 10 characters).
3. **Theme**: pick one of the four themes (changeable later under Design).
4. **Content**: optionally load the demo content (a fictional association
   with original artwork and radio programmes) to see every feature, or start
   empty. The wizard then locks: every `/install` URL returns 404.

Then take write access to the site folder away again and make
`config.php` readable, but not writable, by the web server:

```bash
cd <site>
chown root:root . && chmod 755 .               # web user can no longer create files in the root
chown root:www config.php && chmod 640 config.php
ls -l config.php                               # -rw-r----- root www
rm -f storage/install-token                    # normally already gone
```

(`storage/` and `public/uploads/` stay owned by `www`.)

Installing by hand instead: `cp config.example.php config.php`, fill in the
values with the aaPanel file editor, including an `app_key` of at least 32
characters generated on the server with
`php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'` (the site refuses to run,
and cron refuses to start, while `app_key` is empty, `change-me` or too
short), `chown root:www config.php && chmod 640 config.php`, then as the web
user: `su -s /bin/sh -c "php bin/migrate && php bin/make-admin you@example.org --name='Your Name'" www`
(it asks for the password).

**Behind a proxy or CDN** (Cloudflare, a load balancer): Gather ignores
`X-Forwarded-For` / `X-Forwarded-Proto` unless you list the proxy's IP
addresses in `config.php`: `'trusted_proxies' => ['203.0.113.10']`. Without
that, rate limits see the proxy's address and HTTPS is detected from the
direct connection only. Leave it empty when Apache faces the internet
directly (the normal aaPanel setup).

## 6. Cron (one line)

Gather has one dispatcher that runs every due job: scheduled publishing,
the email queue (campaigns, notices, birthday emails), birthdays, job expiry,
clean-up, the purge of unverified sign-ups and the daily backup.

aaPanel → **Cron → Add task**:

- Type: **Shell script**, period: **every 1 minute** (N minutes = 1).
- Script (use the full PHP path of the site's version, not plain `php`,
  which can be an older CLI; run it as `www` so files it creates stay
  writable by the site):

  ```bash
  su -s /bin/sh -c "/www/server/php/<ver>/bin/php <site>/bin/cron >> <site>/storage/logs/cron.log 2>&1" www
  ```

Check after two minutes: **Admin → System health → Cron** shows "last run"
within the last minute and every job green. If cron stops, scheduled posts
and events still go live on the first page view after their time, and the
health page warns.

## 7. After the install

1. **Admin → Email settings**: switch to **SMTP** (your mail provider's host,
   port 587 + STARTTLS or 465 + SSL, user and password; the password is stored
   encrypted), set the sender address, then **Send a test email**. Until then
   emails are only written to `storage/mail/`.
2. **Admin → System health**: everything should be OK. Typical items to fix:
   upload limits (step 4), missing `intl`/`exif`, cron (step 6), the site
   address (must start with `https://`; edit `base_url` in `config.php` if
   you installed before enabling SSL).
3. **Admin → Users and roles**: add the other admins and tick only the areas
   each one manages. Keep at least two super admins so one can always help
   the other (Gather never lets the last one be demoted or suspended).
4. **Admin → Site settings**: identity, contact, donation links; analytics
   only if you want it (cookie banner appears only for providers that set
   cookies).

## 8. Check it

Read-only checks (paste the output back if something looks wrong):

```bash
cd <site>
/www/server/php/<ver>/bin/php -v | head -1
find . -name '*.php' -print0 | xargs -0 -n1 /www/server/php/<ver>/bin/php -l | grep -v '^No syntax errors' || echo "all files parse"
curl -s -o /dev/null -w 'home %{http_code}\n' https://<domain>/
curl -s -o /dev/null -w 'config.php %{http_code} (want 403/404)\n' https://<domain>/config.php
curl -s -o /dev/null -w 'src %{http_code} (want 403/404)\n' https://<domain>/src/bootstrap.php
curl -s -o /dev/null -w 'storage %{http_code} (want 403/404)\n' https://<domain>/storage/logs/php-error.log
curl -s -o /dev/null -w 'install %{http_code} (want 404)\n' https://<domain>/install
curl -sI https://<domain>/ | grep -iE 'content-security|x-content|strict-transport|x-frame|x-powered-by'
tail -n 20 storage/logs/php-error.log 2>/dev/null
```

Expected headers: `Content-Security-Policy`, `X-Content-Type-Options:
nosniff`, `Strict-Transport-Security: max-age=31536000; includeSubDomains`
(so every subdomain of `<domain>` must serve HTTPS too; Gather does not send
`preload`), `X-Frame-Options: SAMEORIGIN`, and no `X-Powered-By`. Then open the site on a phone, sign up as a test member, use
the contact form, and play the radio once.

## 9. Backups

Two layers, both on:

- **Gather → Backups** (super admin): download the database (SQL, gzip) and
  the uploads (ZIP) at any time; switch on **Make a backup every day** (time,
  how many to keep, with or without uploads). Files land in
  `storage/backups/` (not web-reachable, mode 640) and old ones are deleted
  automatically. Needs the cron line.
- **aaPanel → Cron**: add a **Backup site** and a **Backup database** task,
  daily, keeping 7 to 14 copies.

Backups contain members' personal data. Keep copies that leave the server
encrypted, and do one **test restore** before you rely on them:

```bash
# on a fresh copy of the site (same steps 2-4, with config.php filled in):
su -s /bin/sh -c "/www/server/php/<ver>/bin/php bin/restore /path/gather-YYYYmmdd-HHMMSS-db.sql.gz" www   # asks you to type the database name
su -s /bin/sh -c "/www/server/php/<ver>/bin/php bin/migrate" www
unzip -o /path/gather-YYYYmmdd-HHMMSS-uploads.zip -d <site> && chown -R www:www <site>/storage <site>/public/uploads
```

## 10. Updating

1. Back up: **Gather → Backups → Back up to the server now** (tick "Include
   uploaded files"), or run the two aaPanel backup tasks once by hand.
2. On the Mac: `bin/check`, commit, `bin/package`.
3. Upload the new archive to `<site>` and unpack it over the old files:
   ```bash
   cd <site>
   tar -xzf gather-*.tar.gz --strip-components=1 && rm gather-*.tar.gz
   find . -name '._*' -type f -delete
   chown -R root:root src templates themes migrations bin vendor demo-assets VERSION
   find public -path public/uploads -prune -o -exec chown root:root {} +
   chmod 755 bin/*
   chown -R www:www storage public/uploads
   su -s /bin/sh -c "/www/server/php/<ver>/bin/php bin/migrate" www     # forward-only SQL migrations
   ```
   `bin/migrate` also moves media files to match the visibility of the items
   that use them and re-encrypts a stored SMTP password after an upgrade; it
   warns if `app_key` is missing or too short.
   `config.php`, `storage/`, `public/uploads/` contents and `.user.ini` are
   not in the archive, so they survive. Files removed from Gather in a new
   version stay behind; they are harmless (only `public/` is served), or
   compare against the archive's file list to tidy up.
4. Reload PHP if you use OPcache with `validate_timestamps=0`.
5. Repeat the checks in step 8 and look at **System health** (Migrations: none
   pending).

## Troubleshooting

| Symptom | Look at |
|---|---|
| Blank page or "Something went wrong" | `storage/logs/php-error.log`, then the site's Apache error log (site Settings → Logs) |
| 404 on every page except the home page | Running directory is not `/public`, or `mod_rewrite` / `.htaccess` is not active |
| Redirect loop to `/install` | `config.php` missing or `installed` is false; the wizard was not finished |
| "open_basedir restriction in effect" | A path outside the site folder: check `.user.ini` contains `<site>/:/tmp/` |
| Uploads fail (large files) | `upload_max_filesize` / `post_max_size` (step 4); System health → Uploads |
| Upload fails silently / permission denied | `storage/` and `public/uploads/` must be owned by `www` |
| Images show but no thumbnails | GD without WebP: System health → "GD WebP support" |
| Emails not arriving | Email settings → Send a test email; Delivery log; System health → Mail transport; cron running? |
| Scheduled posts late, campaigns not sending | Cron line (step 6): full PHP path, runs as `www`; System health → Cron |
| Files in `storage/` owned by root | Cron ran as root: fix the cron line, then `chown -R www:www storage public/uploads` |
| "This site is not configured correctly: the secret key…" | `app_key` in `config.php` is empty, `change-me` or shorter than 32 characters: generate one (step 5) |
| `/install` says "Set an install token first" | Create `storage/install-token` (step 5) |
| Emails stop, health says "Mail server unreachable" | Sending pauses (5 min up to 1 h) while the SMTP server is down or rejects the login; nothing is lost. Fix the settings or wait; the next cron run resumes |
| Radio seeking does not work | PHP serves media with byte ranges; check nothing in front (CDN) strips `Range` headers |
